# Fact Check mode

Use this mode when the user wants current facts, supplies specific products or routes, or asks to verify claims before comparing options.

## Research standard

- Browse for information that can change, including prices, schedules, availability, policies, product specifications, and travel requirements.
- Prefer primary sources: airlines, hotels, official transport operators, product manufacturers, government agencies, and the user's supplied booking page.
- Use reputable secondary sources for lived experience, recurring operational problems, or comparisons that primary sources do not cover.
- Record the date, market, currency, fare class, room type, route, and other qualifiers that affect comparability.
- Do not claim a price or availability is live when it comes from a cached result, snippet, or inaccessible logged-in page.
- Cite each material factual claim near the claim.

## Separate three layers

Label the result so the user can see what came from where:

1. **Verified fact:** supported by a current source.
2. **Assumption:** needed for the model but not verified.
3. **Preference:** a value judgment that only the user can supply.

Resolve conflicts explicitly. If two sources disagree, show the disagreement and use a range or scenarios rather than choosing the convenient number.

## Travel details

For flights, distinguish scheduled arrival from usable arrival time. Check airports, terminals, baggage rules, minimum connection time when authoritative data is available, overnight timing, hotel check-in constraints, ground transport, and whether the itinerary is protected on one ticket. Never infer that two flight numbers form a protected connection without evidence.
